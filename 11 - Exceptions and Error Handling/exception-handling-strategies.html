📌 Exception Handling Strategies

🛑 The Impact of Poor Exception Handling

When building something like an Amazon checkout, developers usually focus on the "Happy Path" (Add to Cart -> Add Address -> Pay -> Success).

But what if the OTP is not delivered? If the user just sees a blank screen or a vague "Something went wrong" message, it leads to:

  • Failed Transactions & Cart Abandonment.
  • Angry Customers and Bad PR.

Good Exception Handling involves:

  1. Showing a proper, actionable error message.
  2. Logging the root cause for developers.
  3. Triggering alerts (PagerDuty) for critical failures.
  4. Retrying safely or failing gracefully.

⚖️ Fail-Fast vs Fail-Safe

Two primary architectural approaches to handling errors:

Aspect💥 Fail-Fast🛟 Fail-Safe
What it doesDetects errors early and stops execution immediately.Continues running despite errors using fallbacks.
When to usePayment processing, Data Integrity validation.User UI, Healthcare, Video Streaming.
ExampleStopping a car if tire pressure is zero.Using a secondary plane engine if the first fails.
Code StructureCheck input -> Throw exception immediately.try -> catch -> return default value.

Fail-Fast Code Example

cpp
Product getProduct(const string& productId) {
    if (productId.empty()) {
        throw invalid_argument("Product ID cannot be empty"); // Fails immediately!
    }
    return fetchProduct(productId);
}

Fail-Safe Code Example

cpp
Product getProduct(const string& productId) {
    try {
        return fetchProduct(productId);
    } catch (const exception& e) {
        return Product("default", "Fallback Product"); // Keeps system running!
    }
}

✅ Checked vs Unchecked Exceptions

While languages like Java enforce Checked exceptions at compile time, C++ does not. However, conceptually, we treat them similarly:

1. Checked Exceptions (Recoverable)

  • These represent recoverable conditions (e.g., file not found, network timeout).
  • Developers should explicitly handle these using try-catch.
  • Examples: std::runtime_error, std::ios_base::failure.

2. Unchecked Exceptions (Bugs)

  • These represent programming bugs (e.g., out-of-bounds array access, invalid casts).
  • They should NOT be caught and ignored; the underlying code bug must be fixed!
  • Examples: std::out_of_range, std::invalid_argument.

🛠️ Custom Domain Exceptions

Instead of throwing a generic std::runtime_error, you should create Custom Exceptions tailored to your business logic. This makes debugging incredibly expressive.

cpp
#include <iostream>
#include <exception>

using namespace std;

// 1. Create a custom exception class
class CustomerNotPlusException : public exception {
    string message;
public:
    CustomerNotPlusException(const string& userId) {
        message = "User " + userId + " is not a Plus customer!";
    }

    // Override what() to return the custom message
    const char* what() const noexcept override {
        return message.c_str();
    }
};

class CourseService {
public:
    void accessCourse(const string& userId) {
        if (!hasAccess(userId)) {
            // 2. Throw the custom exception
            throw CustomerNotPlusException(userId);
        }
    }
private:
    bool hasAccess(const string& userId) { return false; }
};

[!tip] Why Custom Exceptions? It allows calling code to separate different error types clearly: catch (const CustomerNotPlusException& e) { showUpgradePrompt(); } catch (const DatabaseException& e) { showRetryMessage(); }

📌 Class Relationships in UML

🎯 Visualizing Relationships

For an in-depth code-level look at these, see [[03 - Class Relationships/association|Module 03: Class Relationships]]. Here, we focus purely on how to draw them in UML.

Mastering these arrows is crucial for both reading system architectures and drawing your own during LLD interviews.

📊 The UML Arrow Cheat Sheet

RelationshipMeaningUML Arrow StyleCode Concept
Dependency"Uses temporarily"- - - > (Dashed line, open arrow)Method parameter, local variable
Association"Knows about"—————→ (Solid line, open arrow)Class field (independent lifecycle)
Aggregation"Has-A (Weak)"◇————— (Solid line, empty diamond)Collection of pointers/refs
Composition"Has-A (Strong)"◆————— (Solid line, filled diamond)Owned object, unique_ptr
Inheritance"Is-A"—————▷ (Solid line, hollow triangle)extends / public Base
Realization"Implements"- - - ▷ (Dashed line, hollow triangle)implements

1. Inheritance (Generalization)

A subclass inherits from a superclass.

  • Line: Solid
  • Head: Hollow triangle pointing to parent
mermaid
classDiagram
    class Animal
    class Dog
    class Cat

    Animal <|-- Dog : extends
    Animal <|-- Cat : extends

2. Realization (Implementation)

A class implements an interface.

  • Line: Dashed
  • Head: Hollow triangle pointing to interface
mermaid
classDiagram
    class Payable {
        <<interface>>
    }
    class Employee
    class Vendor

    Payable <|.. Employee : implements
    Payable <|.. Vendor : implements

3. Composition (Strong "Has-A")

The child dies if the parent is destroyed.

  • Line: Solid
  • Head: Filled diamond at the parent (owner) side
mermaid
classDiagram
    class House
    class Room

    House *-- Room : owns

4. Aggregation (Weak "Has-A")

The child can exist independently of the parent.

  • Line: Solid
  • Head: Hollow/Empty diamond at the parent (container) side
mermaid
classDiagram
    class Department
    class Professor

    Department o-- Professor : contains

5. Association ("Knows about")

Two classes communicate, but neither owns the other.

  • Line: Solid
  • Head: Open arrow pointing to the known class (or no arrow if bidirectional)
mermaid
classDiagram
    class Student
    class Course

    Student --> Course : enrolls in

6. Dependency ("Uses")

A class uses another class temporarily (e.g., passing it into a function).

  • Line: Dashed
  • Head: Open arrow pointing to the used class
mermaid
classDiagram
    class OrderProcessor
    class Logger

    OrderProcessor ..> Logger : uses

🧠 Memory Trick for Interviews

  1. Triangles (▷) = Hierarchy. Solid line = Class inheritance. Dashed line = Interface implementation.
  2. Diamonds (◆ / ◇) = Ownership. Filled = Strong ownership (Composition). Empty = Weak ownership (Aggregation).
  3. Arrows (→) = Usage. Solid = Persistent usage (Association). Dashed = Temporary usage (Dependency).

[!quote] Key Takeaway The shape of the arrow head and the line type (solid vs dashed) tell you exactly how tightly coupled two classes are.

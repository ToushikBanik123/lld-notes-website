🎯 What is the Memento Pattern?

The Memento Pattern is a behavioral design pattern that allows an object to capture its internal state and restore it later—without violating encapsulation.

It is the classic pattern used to implement Undo/Redo functionality or Save/Load mechanisms.

[!example] Real-World Analogy 🎮 Think of a Video Game Save File. You play a game, reach a checkpoint, and the game saves your state (health, inventory, level). Later, if you die, you can load that save file. The save file (Memento) is stored on your hard drive (Caretaker), but only the Game Engine (Originator) knows how to read and write the data inside it.

⚠️ The Problem: Breaking Encapsulation for Undo

Imagine building a text or resume editor. To implement "Undo", you might be tempted to just copy the object's state from the outside.

cpp
// ❌ BAD PRACTICE: Breaking Encapsulation
class ResumeEditor {
public: // Oh no, everything is public so the outside world can save it!
    string name;
    string experience;
    vector<string> skills;
};

// Client code trying to manage state manually
ResumeEditor editor;
// ... editing ...
string savedName = editor.name; // Tight coupling to internal structure!
// If ResumeEditor changes 'name' to a 'struct PersonName', client code breaks.

🛠️ The Solution: Originator, Memento, and Caretaker

The pattern introduces three roles to safely manage state:

  1. Originator: The actual object doing the work (e.g., ResumeEditor). It is the only one allowed to create and read Mementos.
  2. Memento: A simple data container holding the saved state. It is immutable to the outside world.
  3. Caretaker: Holds onto the Mementos (e.g., a History Stack) but never peeks inside them.

1. The Originator & Inner Memento Class

In C++, we can use nested classes or friend classes to ensure only the Originator can access the Memento's data.

cpp
#include <iostream>
#include <string>
#include <vector>
#include <stack>
using namespace std;

class ResumeEditor {
private:
    string name;
    string experience;
    vector<string> skills;

public:
    // --- Business Logic ---
    void setExperience(const string& exp) { experience = exp; }
    // ... other setters/getters ...

    // ==========================================
    // 2. The Memento (Nested Class)
    // ==========================================
    class Memento {
    private: // Private! Only accessible by ResumeEditor (Outer class)
        string name;
        string experience;
        vector<string> skills;

        // Constructor is private/protected so only Originator can create it
        Memento(string n, string e, vector<string> s) 
            : name(n), experience(e), skills(s) {}
        
        friend class ResumeEditor; // Outer class can access private members
    };
    // ==========================================

    // --- State Management ---
    // Save current state into a Memento
    Memento save() {
        return Memento(name, experience, skills);
    }

    // Restore state from a Memento
    void restore(const Memento& m) {
        name = m.name;
        experience = m.experience;
        skills = m.skills;
    }
};

3. The Caretaker

The Caretaker manages the history. Notice it uses ResumeEditor::Memento, but because the Memento's data is private, the Caretaker cannot alter or read the data! It just holds it.

cpp
class ResumeHistory {
private:
    stack<ResumeEditor::Memento> history; // The undo stack

public:
    void save(ResumeEditor& editor) {
        history.push(editor.save());
    }

    void undo(ResumeEditor& editor) {
        if (!history.empty()) {
            editor.restore(history.top());
            history.pop();
        }
    }
};

4. Client Code

cpp
int main() {
    ResumeEditor editor;
    ResumeHistory history;

    // Step 1: Make edits and save
    editor.setExperience("Fresher");
    history.save(editor); // Snapshot 1

    // Step 2: Make more edits
    editor.setExperience("Senior Engineer");
    history.save(editor); // Snapshot 2

    // Step 3: Undo
    history.undo(editor); // Reverts to "Senior Engineer"
    history.undo(editor); // Reverts to "Fresher"
}

✅ Pros and Cons

ProsCons
Encapsulation intact: State is saved without exposing object internalsHigh RAM usage: Storing many large mementos (like massive images) will consume a lot of memory
Clean Caretaker: History management is extracted out of the main business logicCaretaker Complexity: The caretaker needs to know when to delete old mementos to prevent memory leaks

[!tip] Memento vs. Command for Undo Both patterns can implement Undo.

  • Memento saves the entire state (like a snapshot). Good for small objects.
  • Command saves the action taken (like a diff). Good for massive objects (like a Photoshop canvas) where full snapshots are too heavy. They are often used together!

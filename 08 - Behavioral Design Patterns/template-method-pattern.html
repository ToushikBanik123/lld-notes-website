🎯 What is the Template Method Pattern?

The Template Method Pattern defines the skeleton (the template) of an algorithm in a base class but lets subclasses override specific steps of the algorithm without changing its overall structure.

[!example] Real-World Analogy 🍰 Think of Baking a Cake. The recipe (the template) is always the same:

  1. Mix ingredients
  2. Bake
  3. Add Frosting

However, a Chocolate Cake overrides Step 1 to add cocoa powder, while a Vanilla Cake overrides Step 3 to add vanilla frosting. The process remains identical, but the details change.

⚠️ The Problem: Code Duplication in Similar Processes

Imagine building a Data Mining tool that extracts data from PDFs and CSVs. The process is almost identical: open file, extract data, parse data, analyze, and close file.

cpp
// ❌ BAD PRACTICE: Duplicating the workflow
class PDFDataMiner {
public:
    void mine(string path) {
        openFile(path);       // Shared logic
        extractPDFData();     // UNIQUE logic
        parseData();          // Shared logic
        analyze();            // Shared logic
        closeFile();          // Shared logic
    }
};

class CSVDataMiner {
public:
    void mine(string path) {
        openFile(path);       // Shared logic! DUPLICATED!
        extractCSVData();     // UNIQUE logic
        parseData();          // Shared logic! DUPLICATED!
        analyze();            // Shared logic! DUPLICATED!
        closeFile();          // Shared logic! DUPLICATED!
    }
};

If we want to change how analyze() works, we have to change it in every single miner class. This violates the DRY (Don't Repeat Yourself) principle.

🛠️ The Solution: The Template Method

We create an abstract base class containing the mine() method. This is the Template Method. It calls a series of steps. We implement the shared steps directly in the base class, and declare the unique steps as pure virtual (abstract) so subclasses must implement them.

1. The Abstract Base Class

[!warning] C++ Note In C++, we don't have a final keyword for methods in the same way Java does (though C++11 added final for overrides). We usually just make the template method non-virtual so subclasses shouldn't override the skeleton itself.

cpp
#include <iostream>
#include <string>
using namespace std;

class DataMiner {
public:
    virtual ~DataMiner() = default;

    // The Template Method: Non-virtual so subclasses don't change the workflow!
    void mine(const string& path) {
        openFile(path);
        extractData(); // Abstract step
        parseData();
        analyze();
        closeFile(path);
    }

protected:
    // --- Concrete Steps (Shared Logic) ---
    void openFile(const string& path) { cout << "Opening file: " << path << "\n"; }
    void parseData() { cout << "Parsing extracted data...\n"; }
    void analyze() { cout << "Analyzing data patterns...\n"; }
    void closeFile(const string& path) { cout << "Closing file: " << path << "\n"; }

    // --- Abstract Steps (Unique Logic) ---
    virtual void extractData() = 0; 
    
    // --- Optional "Hooks" ---
    // A hook is an optional step with an empty or default implementation.
    virtual void customReporting() { 
        // Do nothing by default. Subclasses CAN override if they want.
    }
};

2. Concrete Subclasses

The subclasses only implement the specific steps they need to change.

cpp
class PDFDataMiner : public DataMiner {
protected:
    void extractData() override {
        cout << "Extracting text from PDF using OCR...\n";
    }
};

class CSVDataMiner : public DataMiner {
protected:
    void extractData() override {
        cout << "Extracting rows from CSV using comma delimiters...\n";
    }
};

3. Client Code

cpp
int main() {
    PDFDataMiner pdfMiner;
    pdfMiner.mine("report.pdf"); 
    // Output:
    // Opening file: report.pdf
    // Extracting text from PDF using OCR...
    // Parsing extracted data...
    // Analyzing data patterns...
    // Closing file: report.pdf

    cout << "\n";

    CSVDataMiner csvMiner;
    csvMiner.mine("data.csv");
}

⚖️ Template Method vs. Strategy

AspectTemplate MethodStrategy Pattern
MechanismUses Inheritance (Subclassing)Uses Composition (Object references)
Level of ModificationModifies parts of an algorithmReplaces the entire algorithm
CouplingTightly coupled (Subclasses depend on the Base class)Loosely coupled (Clients can swap strategies at runtime)

✅ Pros and Cons

ProsCons
DRY Principle: Eliminates code duplication by pulling common logic up to a base classRigidity: Clients are locked into the specific skeleton defined by the base class
Control: The base class dictates the overall flow, preventing subclasses from messing up the required sequence of operationsInheritance Limits: In languages without multiple inheritance, occupying the base class slot might limit future design choices
Hooks: Allows optional injection points for subclasses

[!quote] Key Takeaway Use the Template Method pattern when you have several classes that contain almost identical algorithms with minor variations. Put the common workflow into a base class and let subclasses fill in the blanks.

📌 Designing an ATM Machine

🎯 Step 1: Clarify Requirements

Functional Requirements

  1. Authentication: Must insert card and enter PIN to authenticate.
  2. Operations: Supported operations are Check Balance, Withdraw Cash, Deposit Cash.
  3. Session: Only one active session per ATM at a time.
  4. States: The ATM moves through strictly controlled states: Idle → CardInserted → Authenticated → TransactionSelected → Completed.

Non-Functional Requirements

  1. Security: Cannot perform transactions without authentication.
  2. Precision: Use minor units (cents) for currency to avoid floating-point math issues.
  3. Concurrency: ATM limits hardware concurrency by strictly managing sessions via State.

🧱 Step 2: Identify Core Entities

  1. ATM: Context object holding hardware components (CashDrawer, CardReader) and current ATMState.
  2. Card & Account: Defines the user and their bank limits.
  3. Transaction: A record of Withdraw, Deposit, or Balance check.
  4. ATMState: Interface defining the ATM's operational flow.

⚙️ Step 3: Architecture & Design Patterns

  1. State Pattern: Like the Vending Machine, State is paramount here. Prevents a user from withdrawing cash before entering a PIN.
  2. Strategy Pattern: Used to process different TransactionTypes. Instead of a massive switch statement, WithdrawalStrategy, DepositStrategy, and BalanceInquiryStrategy handle their specific rules.

💻 Step 4: Core Implementation (C++)

cpp
#include <iostream>
#include <string>
#include <memory>
#include <stdexcept>

using namespace std;

class ATM;

// 1. State Pattern Interface
class ATMState {
public:
    virtual void insertCard(ATM* atm, string cardNumber) = 0;
    virtual void enterPin(ATM* atm, string pin) = 0;
    virtual void selectTransaction(ATM* atm, string type) = 0;
    virtual void ejectCard(ATM* atm) = 0;
    virtual string getName() = 0;
    virtual ~ATMState() = default;
};

// Base class to provide default throwing behavior
class AbstractATMState : public ATMState {
public:
    void insertCard(ATM* atm, string cardNumber) override { throw runtime_error("Cannot insert card in current state: " + getName()); }
    void enterPin(ATM* atm, string pin) override { throw runtime_error("Cannot enter PIN in current state: " + getName()); }
    void selectTransaction(ATM* atm, string type) override { throw runtime_error("Cannot select transaction in current state: " + getName()); }
    void ejectCard(ATM* atm) override { throw runtime_error("Cannot eject card in current state: " + getName()); }
};

// 2. The Context (ATM)
class ATM {
public:
    unique_ptr<ATMState> state;
    string currentCard;

    ATM();
    void setState(unique_ptr<ATMState> newState) { state = move(newState); }

    void insertCard(string card) { state->insertCard(this, card); }
    void enterPin(string pin) { state->enterPin(this, pin); }
    void selectTransaction(string type) { state->selectTransaction(this, type); }
    void ejectCard() { state->ejectCard(this); }
};

// 3. Concrete States
class IdleState : public AbstractATMState {
public:
    void insertCard(ATM* atm, string cardNumber) override;
    string getName() override { return "IDLE"; }
};

class CardInsertedState : public AbstractATMState {
public:
    void enterPin(ATM* atm, string pin) override;
    void ejectCard(ATM* atm) override;
    string getName() override { return "CARD_INSERTED"; }
};

class AuthenticatedState : public AbstractATMState {
public:
    void selectTransaction(ATM* atm, string type) override;
    void ejectCard(ATM* atm) override;
    string getName() override { return "AUTHENTICATED"; }
};

// State Implementations
void IdleState::insertCard(ATM* atm, string cardNumber) {
    cout << "Card " << cardNumber << " inserted." << endl;
    atm->currentCard = cardNumber;
    atm->setState(make_unique<CardInsertedState>());
}

void CardInsertedState::enterPin(ATM* atm, string pin) {
    // In a real system, validate against bank service
    if (pin == "1234") {
        cout << "PIN accepted." << endl;
        atm->setState(make_unique<AuthenticatedState>());
    } else {
        cout << "Wrong PIN." << endl;
        ejectCard(atm);
    }
}
void CardInsertedState::ejectCard(ATM* atm) {
    cout << "Ejecting card." << endl;
    atm->currentCard = "";
    atm->setState(make_unique<IdleState>());
}

void AuthenticatedState::selectTransaction(ATM* atm, string type) {
    cout << "Processing Transaction: " << type << endl;
    // ... delegate to TransactionStrategy ...
    cout << "Transaction Complete. Ejecting card." << endl;
    atm->currentCard = "";
    atm->setState(make_unique<IdleState>()); // End session
}
void AuthenticatedState::ejectCard(ATM* atm) {
    cout << "Ejecting card." << endl;
    atm->currentCard = "";
    atm->setState(make_unique<IdleState>());
}

ATM::ATM() {
    state = make_unique<IdleState>();
}

// Usage
int main() {
    ATM atm;
    atm.insertCard("1234-5678");
    atm.enterPin("1234");
    atm.selectTransaction("WITHDRAW");

    return 0;
}

🚨 Edge Cases Handled

  • Invalid Operations: AbstractATMState provides a safe default where all methods throw exceptions. Concrete states only override the methods that are valid for their specific step in the flow.
  • Hardware Simulation: The state machine cleanly replicates the strict physical limitations of ATM hardware.

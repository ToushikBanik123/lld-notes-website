📌 Designing a PubSub System

[!info] Navigation Module: [[14 - Interview Problems Part 2/index|← Interview Problems Part 2 Overview]] Prev: [[14 - Interview Problems Part 2/hotel-management-system|← Designing a Hotel Management System]] Next: [[15 - Interview Problems Part 3/index|Interview Problems Part 3 →]]

🎯 Step 1: Clarify Requirements

Functional Requirements

  1. Topics: System supports creating multiple Topics.
  2. Publishers: Can publish messages to a specific Topic.
  3. Subscribers: Can subscribe to multiple Topics.
  4. Delivery: When a message is published, all subscribers of the Topic receive it.
  5. Delivery Channels: Support multiple types of subscribers (e.g., Email, Realtime/WebSocket).

Non-Functional Requirements

  1. Thread Safety: The system must be thread-safe. Publishers publishing to a topic shouldn't crash if a subscriber subscribes at the exact same millisecond.
  2. Asynchronous Execution: Fan-out notification should happen asynchronously to prevent blocking the Publisher.

🧱 Step 2: Identify Core Entities

  1. Topic: Contains metadata and owns the Observer list (Subject).
  2. Message: Payload, timestamp.
  3. SubscriberObserver (Interface): The Observer interface.
  4. EmailSubscriber, RealtimeSubscriber: Concrete Observers.

⚙️ Step 3: Architecture & Design Patterns

  1. Observer Pattern: The core of the system. The Topic is the Subject. The Subscribers are the Observers.
  2. Multithreading: Utilize std::mutex to protect the observer list. Utilize std::async to execute the fan-out asynchronously.

💻 Step 4: Core Implementation (C++)

cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <mutex>
#include <future>

using namespace std;

// 1. Entities
struct Message {
    string content;
    long long timestamp;
};

// 2. Observer Pattern Interface
class SubscriberObserver {
public:
    virtual void update(shared_ptr<Message> msg) = 0;
    virtual ~SubscriberObserver() = default;
};

// Concrete Observers
class EmailSubscriber : public SubscriberObserver {
    string email;
public:
    EmailSubscriber(string e) : email(e) {}
    void update(shared_ptr<Message> msg) override {
        cout << "📧 [Email -> " << email << "] Received: " << msg->content << endl;
    }
};

class RealtimeSubscriber : public SubscriberObserver {
    string connectionId;
public:
    RealtimeSubscriber(string connId) : connectionId(connId) {}
    void update(shared_ptr<Message> msg) override {
        cout << "⚡ [WebSocket -> " << connectionId << "] Received: " << msg->content << endl;
    }
};

// 3. Subject (The Topic)
class Topic {
private:
    string name;
    vector<shared_ptr<SubscriberObserver>> subscribers;
    mutable mutex mtx; // Protects the subscriber list

public:
    Topic(string n) : name(n) {}

    void subscribe(shared_ptr<SubscriberObserver> sub) {
        lock_guard<mutex> lock(mtx);
        subscribers.push_back(sub);
        cout << "System: New subscriber attached to " << name << endl;
    }

    void publish(shared_ptr<Message> msg) {
        // Copy the subscriber list under lock so we don't hold the lock during long fan-outs
        vector<shared_ptr<SubscriberObserver>> snapshot;
        {
            lock_guard<mutex> lock(mtx);
            snapshot = subscribers;
        }

        // Fan-out asynchronously
        auto future = async(launch::async, [snapshot, msg]() {
            for (const auto& sub : snapshot) {
                sub->update(msg);
            }
        });
        
        // In a real system, you might store the future or detach to truly fire-and-forget
        future.wait(); // Wait here just to make console output predictable for the demo
    }
};

// Usage
int main() {
    // 1. Create Topic
    auto topic = make_shared<Topic>("TECH_NEWS");

    // 2. Create Subscribers
    auto alice = make_shared<EmailSubscriber>("alice@example.com");
    auto bob = make_shared<RealtimeSubscriber>("conn_bob_123");

    // 3. Subscribe
    topic->subscribe(alice);
    topic->subscribe(bob);

    // 4. Publish Message
    auto msg = make_shared<Message>(Message{"New C++ Standard Released!", 123456789});
    cout << "\nPublisher: Publishing message..." << endl;
    topic->publish(msg);

    return 0;
}

🚨 Edge Cases Handled

  • Concurrent Sub/Pub: By protecting the observer list with std::mutex, the system prevents undefined behavior if a user subscribes while a publish is iterating over the list.
  • Lock Contention: To avoid blocking new subscribers while a slow fan-out occurs (e.g. sending 10,000 emails), the Topic::publish() method takes a snapshot copy of the subscribers vector while under the lock, releases the lock, and then iterates over the snapshot.
  • Async Execution: Using std::async, the publisher is unblocked immediately after the snapshot is taken, increasing system throughput.

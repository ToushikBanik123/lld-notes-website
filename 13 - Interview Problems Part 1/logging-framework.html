📌 Designing a Logging Framework

[!info] Navigation Module: [[13 - Interview Problems Part 1/index|← Interview Problems Part 1 Overview]] Next: [[13 - Interview Problems Part 1/parking-lot|Designing a Parking Lot System →]]

🎯 Step 1: Clarify Requirements

Functional Requirements

  1. Log Levels: Support DEBUG, INFO, WARNING, ERROR, FATAL. Priority-based filtering (e.g., if set to WARNING, only log WARNING, ERROR, FATAL).
  2. Message Structure: Must include timestamp, level, message text, and optional source (class/method).
  3. Multiple Outputs (Appenders): Console, File, Database. A single message can go to multiple destinations.
  4. Configuration: Ability to set log level and configure appenders at runtime.

Non-Functional Requirements

  1. Thread Safety: Multiple threads should be able to log simultaneously without race conditions or data corruption.
  2. Extensibility: Easy to add new appenders (e.g., Email, Network) or new formatters.

🧱 Step 2: Identify Core Entities

  1. LogLevel (Enum): Defines severity and priority.
  2. LogMessage: Immutable object containing timestamp, level, message, and source.
  3. Logger (Singleton/Core Interface): The main entry point for the application to push logs.
  4. LogAppender (Interface): Defines the destination strategy.
  5. LogFormatter (Interface): Defines how the LogMessage is serialized to a String.

⚙️ Step 3: Architecture & Design Patterns

We will heavily rely on standard design patterns:

  1. Strategy Pattern: For formatting (SimpleFormatter, DetailedFormatter) and Appending (ConsoleAppender, FileAppender).
  2. Chain of Responsibility Pattern: (Optional) If implementing complex filtering.
  3. Builder Pattern: For constructing complex LogMessage objects cleanly.
  4. Singleton Pattern: For the central LoggerImpl to ensure one global configuration.

💻 Step 4: Core Implementation (C++)

cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <mutex>
#include <chrono>
#include <ctime>

using namespace std;

// 1. Log Levels
enum class LogLevel {
    DEBUG = 1,
    INFO = 2,
    WARNING = 3,
    ERROR = 4,
    FATAL = 5
};

// 2. Log Message Object
class LogMessage {
public:
    LogLevel level;
    string message;
    string timestamp;

    LogMessage(LogLevel lvl, const string& msg) : level(lvl), message(msg) {
        auto now = chrono::system_clock::now();
        time_t time = chrono::system_clock::to_time_t(now);
        string t = ctime(&time);
        t.pop_back(); // Remove newline
        timestamp = t;
    }
};

// 3. Formatters (Strategy)
class LogFormatter {
public:
    virtual string format(const LogMessage& msg) = 0;
    virtual ~LogFormatter() = default;
};

class SimpleFormatter : public LogFormatter {
public:
    string format(const LogMessage& msg) override {
        return "[" + msg.timestamp + "] - " + msg.message;
    }
};

// 4. Appenders (Strategy)
class LogAppender {
protected:
    shared_ptr<LogFormatter> formatter;
public:
    LogAppender(shared_ptr<LogFormatter> fmt) : formatter(fmt) {}
    virtual void append(const LogMessage& msg) = 0;
    virtual ~LogAppender() = default;
};

class ConsoleAppender : public LogAppender {
public:
    ConsoleAppender(shared_ptr<LogFormatter> fmt) : LogAppender(fmt) {}
    void append(const LogMessage& msg) override {
        cout << formatter->format(msg) << endl;
    }
};

// 5. The Logger (Singleton)
class Logger {
private:
    static shared_ptr<Logger> instance;
    static mutex mtx;

    LogLevel rootLevel;
    vector<shared_ptr<LogAppender>> appenders;

    Logger() {
        rootLevel = LogLevel::INFO; // Default
    }

public:
    static shared_ptr<Logger> getInstance() {
        if (!instance) {
            lock_guard<mutex> lock(mtx);
            if (!instance) {
                instance = shared_ptr<Logger>(new Logger());
            }
        }
        return instance;
    }

    void setLevel(LogLevel level) {
        rootLevel = level;
    }

    void addAppender(shared_ptr<LogAppender> appender) {
        appenders.push_back(appender);
    }

    void log(LogLevel level, const string& message) {
        if (level >= rootLevel) {
            LogMessage msg(level, message);
            lock_guard<mutex> lock(mtx); // Ensure thread-safe publishing
            for (auto& appender : appenders) {
                appender->append(msg);
            }
        }
    }

    // Helper methods
    void info(const string& msg) { log(LogLevel::INFO, msg); }
    void error(const string& msg) { log(LogLevel::ERROR, msg); }
};

// Initialize statics
shared_ptr<Logger> Logger::instance = nullptr;
mutex Logger::mtx;

// Usage
int main() {
    auto logger = Logger::getInstance();
    
    // Configure
    auto formatter = make_shared<SimpleFormatter>();
    auto consoleAppender = make_shared<ConsoleAppender>(formatter);
    logger->addAppender(consoleAppender);

    logger->setLevel(LogLevel::INFO);

    logger->info("Application started");
    logger->debug("This will not be logged");
    logger->error("Database connection failed");

    return 0;
}

🚨 Edge Cases Handled

  • Concurrency: std::mutex wraps the core log method ensuring that multiple threads do not cause race conditions when appending. Double-checked locking used for Singleton initialization.
  • Configurability: Appenders and formatters can be added dynamically.

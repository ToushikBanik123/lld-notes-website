📌 Flyweight Pattern

🎯 What is the Flyweight Pattern?

The Flyweight Pattern is used to minimize memory usage by sharing as much data as possible with similar objects.

It separates an object's state into two parts:

  1. Intrinsic (Shared) State: Immutable data common to many objects (e.g., shape, color, texture).
  2. Extrinsic (Unique) State: Context-specific data passed from the client (e.g., X/Y coordinates).

[!example] Real-World Analogy 🌲 Think of an open-world video game with 1 million trees. All "Oak" trees use the same 3D model and texture (Intrinsic State). However, each tree is planted at a different location on the map (Extrinsic State). Instead of loading the 3D model 1 million times, the game loads it once and just passes the different coordinates to a render function.

⚠️ The Problem: Massive Memory Consumption

If we create a separate object for every single tree, storing the heavy texture data every time, we will quickly run out of RAM.

cpp
// ❌ BAD PRACTICE
class Tree {
    int x, y;                // Small (Extrinsic)
    string name, color, tex; // Heavy (Intrinsic)
public:
    Tree(int x, int y, string n, string c, string t) : x(x), y(y), name(n), color(c), tex(t) {}
};

int main() {
    vector<Tree> forest;
    for(int i=0; i<1000000; i++) {
        // We are duplicating "Oak", "Green", "Rough" 1 million times!
        forest.emplace_back(i, i, "Oak", "Green", "Rough");
    }
}

🛠️ The Solution: Flyweight and Factory

We extract the heavy, shared data into a TreeType class. We use a TreeFactory to ensure we only ever create one instance of each TreeType. The Tree class itself now only holds its coordinates and a pointer to its TreeType.

1. The Flyweight (Intrinsic State)

cpp
class TreeType {
    string name;
    string color;
    string texture;
public:
    TreeType(string n, string c, string t) : name(n), color(c), texture(t) {}
    
    // Extrinsic state is passed in via method arguments
    void draw(int x, int y) const {
        cout << "Drawing " << name << " tree at (" << x << ", " << y << ")\n";
    }
};

2. The Context (Extrinsic State + Flyweight Reference)

cpp
class Tree {
    int x, y; // Unique state
    shared_ptr<const TreeType> type; // Shared state
public:
    Tree(int x, int y, shared_ptr<const TreeType> t) : x(x), y(y), type(t) {}
    void draw() const {
        type->draw(x, y); // Pass extrinsic state to flyweight
    }
};

3. The Flyweight Factory

Ensure flyweights are shared and never duplicated.

cpp
class TreeFactory {
    static unordered_map<string, shared_ptr<const TreeType>> cache;
public:
    static shared_ptr<const TreeType> getTreeType(const string& n, const string& c, const string& t) {
        string key = n + c + t;
        if (cache.find(key) == cache.end()) {
            cache[key] = make_shared<TreeType>(n, c, t);
        }
        return cache[key];
    }
};
unordered_map<string, shared_ptr<const TreeType>> TreeFactory::cache;

4. Client Code

cpp
int main() {
    vector<Tree> forest;
    for(int i=0; i<1000000; i++) {
        auto type = TreeFactory::getTreeType("Oak", "Green", "Rough");
        forest.emplace_back(i, i, type);
    }
    // Result: 1,000,000 Tree objects, but only 1 TreeType object created!
}

✅ Pros and Cons

ProsCons
Saves RAM: Drastically reduces memory consumption for large numbers of objectsComplexity: Code becomes more complicated; state is split across classes
Performance: Faster object creation and less overheadCPU Cost: Accessing extrinsic state might take extra compute cycles compared to direct memory access

[!quote] Key Takeaway Use the Flyweight Pattern strictly for memory optimization when your application needs to spawn millions of identical or very similar objects (like trees in a game, characters in a text editor, or cars on a map).

📌 Deadlocks and Prevention

[!info] Navigation Module: [[09 - Multithreading and Concurrency/index|← Multithreading and Concurrency Overview]] Prev: [[09 - Multithreading and Concurrency/locks-and-synchronization-mechanism|← Locks & Sync Mechanisms]] Next: [[09 - Multithreading and Concurrency/producer-consumer-problem|Producer Consumer Problem →]]

🛑 What is a Deadlock?

A Deadlock is a situation where two or more threads are blocked forever, each waiting for a lock that the other thread holds.

[!example] The Classic Scenario

  • Thread 1 acquires Lock A.
  • Thread 2 acquires Lock B.
  • Thread 1 tries to acquire Lock B (blocks, waiting for T2).
  • Thread 2 tries to acquire Lock A (blocks, waiting for T1). Result: Infinite freeze.

🏛️ The Coffman Conditions

A deadlock CANNOT happen unless ALL FOUR of these conditions are true simultaneously:

  1. Mutual Exclusion: Resources cannot be shared. Only one thread can hold the lock at a time.
  2. Hold and Wait: A thread holds at least one lock while waiting to acquire additional locks.
  3. No Preemption: A lock cannot be forcibly taken away from a thread; the thread must release it voluntarily.
  4. Circular Wait: T1 waits for T2, T2 waits for T3, T3 waits for T1.

Breaking any one of these conditions guarantees your system is deadlock-free.

🛡️ Prevention Strategies

1. Lock Ordering (The simplest fix)

Always acquire locks in the exact same predefined order across all threads. If Thread 1 and Thread 2 both acquire Lock A first, then Lock B, the circular wait condition is broken.

2. Using std::lock for Multiple Mutexes

C++ provides std::lock() which locks multiple mutexes simultaneously using a deadlock avoidance algorithm.

cpp
#include <mutex>

std::mutex mtxA;
std::mutex mtxB;

void threadSafeTransfer() {
    // Tells lock_guard to adopt an already locked mutex
    std::unique_lock<std::mutex> lock1(mtxA, std::defer_lock);
    std::unique_lock<std::mutex> lock2(mtxB, std::defer_lock);
    
    // std::lock acquires both without risk of deadlock
    std::lock(lock1, lock2);
    
    // Transfer logic here...
}

3. Timeouts using try_lock

Break the "No Preemption / Hold and Wait" condition. If a thread cannot acquire all needed locks within a time limit, it releases what it currently holds, backs off, and tries again later.

cpp
while (true) {
    if (mtxA.try_lock()) {
        if (mtxB.try_lock()) {
            // Got both!
            // Work...
            mtxB.unlock();
            mtxA.unlock();
            break;
        } else {
            // Failed B. Release A to avoid deadlock, then try again.
            mtxA.unlock();
            std::this_thread::yield(); 
        }
    }
}

4. Database Deadlock Handling (Wait-Die vs. Wound-Wait)

In distributed systems or databases, deadlocks are often handled based on transaction timestamps (who is older/younger).

StrategyScenario: T1 (Older) wants resource held by T2 (Younger)Scenario: T2 (Younger) wants resource held by T1 (Older)
Wait-DieT1 Waits for T2 to finish.T2 Dies (aborts and retries).
Wound-WaitT1 Wounds T2 (forces T2 to abort).T2 Waits for T1 to finish.

These strategies guarantee progress and prevent cyclic dependencies.

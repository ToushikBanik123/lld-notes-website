🎯 Thread Safety and Race Conditions

Thread Safety means code works correctly when accessed by multiple threads simultaneously. A Race Condition occurs when two or more tasks reach for the same data at the same moment, and the final result depends on unpredictable timing.

Example: Unsafe Counter

cpp
int count = 0;

void increment() {
    count++; // NOT ATOMIC!
}

count++ looks like one step, but it is actually three: READ, ADD 1, WRITE BACK. If two threads read count as 42 simultaneously, both will write 43. One increment vanishes!

🔒 Mutexes (std::mutex)

A Mutex (Mutual Exclusion) primitive ensures only one thread can access a critical section at a time.

1. Manual Lock (Error-Prone)

cpp
mutex mtx;
mtx.lock();
count++;
mtx.unlock(); // What if an exception is thrown before this? Deadlock!

2. std::lock_guard (Recommended)

An RAII wrapper that locks the mutex on creation and automatically unlocks it when it goes out of scope.

cpp
#include <mutex>
using namespace std;

class SafeCounter {
    int count = 0;
    mutex mtx;
public:
    void increment() {
        lock_guard<mutex> guard(mtx); 
        count++; 
        // guard goes out of scope here -> auto-unlocks!
    }
};

3. std::unique_lock

More flexible than lock_guard. Supports manual locking/unlocking, deferred locking, and is required for condition variables.

cpp
unique_lock<mutex> lock(mtx);
count++;
lock.unlock(); // Can explicitly unlock early to reduce lock contention

⚡ The volatile Keyword

volatile tells the compiler: "Do not optimize or cache this variable in a CPU register, read it directly from memory every time."

[!danger] NOT Thread-Safe! volatile does not guarantee atomicity and does not guarantee visibility between threads on different CPU cores. It is meant for memory-mapped hardware registers and signal handlers, NOT for multithreading!

⚛️ Atomic Variables (std::atomic)

C++ provides <atomic> for highly performant, lock-free thread-safe variables.

Atomics use a hardware instruction called CAS (Compare-And-Swap): "If the current value is what I expect it to be, swap it with my new value. Otherwise, retry."

cpp
#include <atomic>
using namespace std;

atomic<int> likes{0};

void incrementLikes() {
    likes.fetch_add(1); // Internally uses CAS, completely lock-free!
    // likes++ is also atomic for std::atomic<int>
}

[!quote] Key Takeaway Use std::atomic for simple counters and flags. Use std::mutex with std::lock_guard for protecting complex data structures (like maps or queues) where multiple variables must be updated together.

📌 Producer Consumer Problem

[!info] Navigation Module: [[09 - Multithreading and Concurrency/index|← Multithreading and Concurrency Overview]] Prev: [[09 - Multithreading and Concurrency/deadlock-and-prevention|← Deadlocks & Prevention]] Next: [[10 - Dependency Injection/index|Dependency Injection →]]

🎯 The Problem

The Producer-Consumer problem is a classic synchronization challenge. We have a Shared Buffer (queue) with a fixed maximum size.

  • Producer: Generates data and puts it into the buffer.
  • Consumer: Removes data from the buffer and processes it.

The Catch

  1. The Producer must not add data if the buffer is FULL.
  2. The Consumer must not remove data if the buffer is EMPTY.
  3. Both must access the buffer safely without causing a race condition.

🛑 The "Busy Wait" Anti-Pattern

A naive approach is to use a simple loop to check the buffer size continually.

cpp
// ANTI-PATTERN! DO NOT DO THIS!
void consumer() {
    while(true) {
        mtx.lock();
        if (!buffer.empty()) {
            // Process item
        }
        mtx.unlock();
        // Spends 100% of CPU just repeatedly locking, checking, and unlocking!
    }
}

💡 The Solution: Condition Variables

A std::condition_variable allows a thread to go to sleep (releasing CPU resources) and wait to be woken up by another thread when a specific condition becomes true.

Required Components

  1. std::mutex to protect the buffer.
  2. std::unique_lock (must be unique_lock, lock_guard will not work).
  3. std::condition_variable to signal state changes.

C++ Implementation

cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <queue>

using namespace std;

queue<int> buffer;
const int MAX_SIZE = 5;

mutex mtx;
condition_variable cv_producer;
condition_variable cv_consumer;

void producer() {
    for (int i = 1; i <= 10; ++i) {
        unique_lock<mutex> lock(mtx);
        
        // Wait UNTIL buffer is not full. 
        // Automatically releases the lock while asleep!
        cv_producer.wait(lock, []() { return buffer.size() < MAX_SIZE; });
        
        buffer.push(i);
        cout << "Produced: " << i << "\n";
        
        // Wake up a sleeping consumer
        cv_consumer.notify_one();
    }
}

void consumer() {
    for (int i = 1; i <= 10; ++i) {
        unique_lock<mutex> lock(mtx);
        
        // Wait UNTIL buffer is not empty.
        cv_consumer.wait(lock, []() { return !buffer.empty(); });
        
        int item = buffer.front();
        buffer.pop();
        cout << "Consumed: " << item << "\n";
        
        // Wake up a sleeping producer
        cv_producer.notify_one();
    }
}

int main() {
    thread t1(producer);
    thread t2(consumer);
    
    t1.join();
    t2.join();
    
    return 0;
}

How wait() works internally:

When cv.wait(lock, condition) is called:

  1. It checks the condition lambda.
  2. If true, it continues executing immediately.
  3. If false, it unlocks the mutex and puts the thread to sleep.
  4. When notify_one() or notify_all() is called by another thread, the sleeping thread wakes up, re-acquires the mutex, and checks the condition again (this loop protects against "spurious wakeups").

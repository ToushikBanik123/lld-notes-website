🎯 Advanced Locking Mechanisms

While std::mutex and std::lock_guard handle 90% of basic use cases, C++ provides specialized locks for complex scenarios to improve performance and prevent deadlocks.

⏱️ std::timed_mutex

A regular std::mutex.lock() blocks forever. A timed_mutex allows a thread to "try" locking for a specific duration. If it fails to acquire the lock in time, it gives up.

[!tip] Use Case Deadlock prevention. If Thread A waits too long for a lock held by Thread B, Thread A can timeout, release its own resources, and try again later.

cpp
#include <iostream>
#include <mutex>
#include <thread>
using namespace std;

timed_mutex t_mtx;

void tryDoingWork(int id) {
    if (t_mtx.try_lock_for(chrono::seconds(2))) {
        cout << "Thread " << id << " acquired lock.\n";
        this_thread::sleep_for(chrono::seconds(5)); // Simulate long work
        t_mtx.unlock();
    } else {
        cout << "Thread " << id << " gave up waiting!\n";
    }
}

📖 std::shared_mutex (Read-Write Lock)

Imagine a forum: thousands of users read a post concurrently, but only one user can edit it. A standard mutex would block readers from reading simultaneously, crippling performance.

A shared_mutex (C++17) solves this:

  • Shared Lock: Multiple threads can acquire the lock simultaneously (for reading).
  • Exclusive Lock: Only ONE thread can acquire the lock, and ONLY IF there are no active shared locks (for writing).
cpp
#include <iostream>
#include <shared_mutex>
#include <thread>
using namespace std;

shared_mutex rw_mtx;
int sharedData = 0;

void reader() {
    // Allows multiple readers simultaneously!
    shared_lock<shared_mutex> lock(rw_mtx);
    cout << "Data: " << sharedData << "\n";
}

void writer() {
    // Requires EXCLUSIVE access. Blocks all readers and other writers.
    unique_lock<shared_mutex> lock(rw_mtx);
    sharedData++;
}

🚦 Semaphores (std::counting_semaphore)

Introduced in C++20. While a Mutex allows exactly 1 thread into a critical section, a Semaphore allows N threads.

[!example] Parking Lot Analogy 🚗 A parking lot has 5 spaces. The boom barrier is the semaphore initialized to 5.

  • A car enters -> Semaphore decrements (acquire()).
  • If Semaphore is 0 -> Barrier stays down, cars wait.
  • A car leaves -> Semaphore increments (release()), barrier lifts for next car.

When to use Semaphores?

  • Limiting concurrent access to a resource (e.g., max 3 active DB connections).
  • Rate Limiting APIs.
cpp
#include <iostream>
#include <semaphore>
#include <thread>
using namespace std;

// Initialize a semaphore that allows exactly 3 threads at a time
counting_semaphore<3> smph(3);

void accessDatabase(int id) {
    smph.acquire(); // Request access (blocks if 0)
    cout << "Thread " << id << " is using DB.\n";
    this_thread::sleep_for(chrono::seconds(2));
    cout << "Thread " << id << " released DB.\n";
    smph.release(); // Free the resource
}

[!info] Binary Semaphore std::binary_semaphore is an alias for std::counting_semaphore<1>. It acts somewhat like a mutex, but importantly, it can be acquired on one thread and released on another thread (which is undefined behavior for a std::mutex).

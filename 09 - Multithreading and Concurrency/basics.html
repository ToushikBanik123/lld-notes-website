📌 Basics of Multithreading and Concurrency

[!info] Navigation Module: [[09 - Multithreading and Concurrency/index|← Multithreading and Concurrency Overview]] Next: [[09 - Multithreading and Concurrency/creating-and-managing-threads|Creating and Managing Threads →]]

🎯 Introduction

Imagine using Netflix: loading video data and buffering happen at the same time, reducing the wait from 10 seconds to 5 seconds. Doing multiple tasks simultaneously is the essence of Multithreading and Concurrency.

🛠️ Program, Process, and Thread

[!example] Bakery Analogy 🍰

  • Program: The Recipe Book (Static instructions).
  • Process: Baking the Cake (The execution of the recipe).
  • Thread: The Bakers (One mixing, one baking, one frosting—working together).
ConceptDescriptionKey Characteristics
ProgramStatic instructions sitting on disk (e.g., chrome.exe).Does nothing until launched.
ProcessA running instance of a program loaded into memory.Fully isolated; has its own memory space. IPC (sockets, files) needed to communicate. "Heavyweight".
ThreadThe smallest unit of execution within a process.Shares memory and resources with other threads in the same process. "Lightweight". Fast context switching.

🧠 CPU Cores and Hyperthreading

A Core is a physical processing unit capable of executing instructions. More cores = more true simultaneous execution.

Hyperthreading (Intel technology) allows one physical core to act as two logical cores. It runs two threads by Intelligent Time Slicing, utilizing idle resources (like when one thread waits on I/O) to run the other thread.

🔄 Context Switching

Context Switching is saving the state of a running thread/process and loading the state of another.

  1. Interrupt: OS pauses the current thread.
  2. Save State: Registers, program counter saved to memory.
  3. Load State: Load data for the next thread.
  4. Switch Execution: CPU executes the new thread.

[!warning] Overhead While context switching allows multitasking, it has overhead. If you have too many threads, the CPU spends more time switching than executing tasks!

⚖️ Concurrency vs. Parallelism

Many confuse these two, but they are fundamentally different:

Concurrency (Juggling)Parallelism (Multiple Jugglers)
Managing multiple tasks over time.Executing tasks at the exact same time.
Can run on a single core via rapid context switching.Requires multiple cores.
Illusion of simultaneous execution.True simultaneous execution.

🔐 Shared vs. Isolated Memory

Shared Memory (Threads)Isolated Memory (Processes)
Memory accessible by multiple threads.Memory dedicated to a single process.
Extremely fast communication.Requires explicit IPC (slower, overhead).
High risk of data corruption / race conditions.Highly secure and stable; crash isolated.

[!tip] When to use which? Use Threads when tasks need to share data, require low overhead, and are highly coupled (e.g., rendering UI). Use Processes when security, isolation, and fault tolerance are strictly required (e.g., browser tabs running in separate processes so one crash doesn't kill the whole browser).

📖 What is Inheritance?

Inheritance is a mechanism where a new class (child/derived) acquires the properties and behaviors of an existing class (parent/base).

[!example] Real-World Analogy 🧬 A child inherits traits from their parents — eye color, height, etc. But they can also develop their own unique traits (overriding or extending).

🧪 Code Example

cpp
#include <iostream>
#include <string>
using namespace std;

// Base class (Parent)
class Animal {
protected:
    string name;
    int age;

public:
    Animal(string n, int a) : name(n), age(a) {}

    void eat() { cout << name << " is eating." << endl; }
    void sleep() { cout << name << " is sleeping." << endl; }

    // Virtual method — can be overridden
    virtual void makeSound() {
        cout << name << " makes a generic sound." << endl;
    }

    virtual ~Animal() {}
};

// Derived class (Child)
class Dog : public Animal {
    string breed;

public:
    Dog(string n, int a, string b) : Animal(n, a), breed(b) {}

    // Override parent method
    void makeSound() override {
        cout << name << " barks! 🐕" << endl;
    }

    // New method specific to Dog
    void fetch() { cout << name << " fetches the ball!" << endl; }
};

class Cat : public Animal {
public:
    Cat(string n, int a) : Animal(n, a) {}

    void makeSound() override {
        cout << name << " meows! 🐱" << endl;
    }

    void purr() { cout << name << " purrs..." << endl; }
};

int main() {
    Dog dog("Buddy", 3, "Golden Retriever");
    Cat cat("Whiskers", 2);

    dog.eat();       // ✅ Inherited from Animal
    dog.makeSound(); // ✅ Overridden: "Buddy barks! 🐕"
    dog.fetch();     // ✅ Dog-specific method

    cat.eat();       // ✅ Inherited from Animal
    cat.makeSound(); // ✅ Overridden: "Whiskers meows! 🐱"
    cat.purr();      // ✅ Cat-specific method

    return 0;
}

[!warning] Diamond Problem Multiple inheritance can cause ambiguity when two parent classes have the same method. C++ solves this with virtual inheritance. Java avoids it entirely by using interfaces instead.

⚖️ Inheritance vs Composition

AspectInheritanceComposition
RelationshipIS-A (Dog is a Animal)HAS-A (Car has a Engine)
CouplingTight (child depends on parent)Loose (objects are independent)
FlexibilityLess flexible (hierarchy is fixed)More flexible (swap at runtime)
When to useNatural hierarchiesBehavior reuse without hierarchy

[!tip] Favor Composition Over Inheritance This is a well-known design principle. Use inheritance for genuine IS-A relationships. Use composition when you just want to reuse behavior.

✅ Quick Revision

[!quote] Key Takeaway Inheritance models IS-A relationships. A Dog IS-A Animal. Use it for natural hierarchies, but prefer composition when you just need to reuse behavior.

📖 What is Abstraction?

Abstraction is the process of hiding complex implementation details and showing only the essential features of an object.

[!example] Real-World Analogy 🚗 When you drive a car, you use:

  • Steering wheel, accelerator, brakes (the interface)

You don't need to know:

  • How the engine combustion works
  • How the transmission shifts gears
  • How the fuel injection system operates

The car abstracts away the complexity.

🔧 How to Achieve Abstraction

1. Abstract Classes

An abstract class is a class that cannot be instantiated and may contain abstract methods (methods without implementation).

cpp
// C++ — Abstract class using pure virtual functions
class Shape {
public:
    // Pure virtual function = abstract method
    virtual double area() = 0;
    virtual double perimeter() = 0;

    // Concrete method (shared by all shapes)
    void display() {
        cout << "Area: " << area()
             << ", Perimeter: " << perimeter() << endl;
    }

    virtual ~Shape() {}
};

class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) {}
    double area() override { return 3.14159 * radius * radius; }
    double perimeter() override { return 2 * 3.14159 * radius; }
};

class Rectangle : public Shape {
    double length, width;
public:
    Rectangle(double l, double w) : length(l), width(w) {}
    double area() override { return length * width; }
    double perimeter() override { return 2 * (length + width); }
};

2. Interfaces

An interface defines a contract — a set of methods that implementing classes must provide.

java
// Java — Interface
interface PaymentGateway {
    boolean processPayment(double amount);
    boolean refund(String transactionId);
    String getGatewayName();
}

class RazorpayGateway implements PaymentGateway {
    public boolean processPayment(double amount) {
        // Razorpay-specific implementation
        System.out.println("Processing via Razorpay: ₹" + amount);
        return true;
    }

    public boolean refund(String txnId) { return true; }
    public String getGatewayName() { return "Razorpay"; }
}

class StripeGateway implements PaymentGateway {
    public boolean processPayment(double amount) {
        // Stripe-specific implementation
        System.out.println("Processing via Stripe: $" + amount);
        return true;
    }

    public boolean refund(String txnId) { return true; }
    public String getGatewayName() { return "Stripe"; }
}

⚖️ Abstract Class vs Interface

FeatureAbstract ClassInterface
Can have constructors?✅ Yes❌ No
Can have instance fields?✅ Yes❌ Only constants
Method implementation?Can have both abstract & concreteOnly abstract (Java 7-), default methods (Java 8+)
Multiple inheritance?❌ One class only✅ Multiple interfaces
When to use?Shared behavior + partial implementationPure contract / capability

[!tip] Rule of Thumb

  • Use abstract class when subclasses share common behavior (IS-A relationship with shared code)
  • Use interface when you want to define a capability that multiple unrelated classes can have

⚖️ Abstraction vs Encapsulation

📖 What is Encapsulation?

Encapsulation is the practice of bundling data (fields) and methods (functions) that operate on that data into a single unit (class), and restricting direct access to some of the object's components.

[!example] Real-World Analogy 💊 Think of a medicine capsule:

  • The medicine (data) is hidden inside the capsule
  • You don't need to know the chemical composition to use it
  • You interact with it through a controlled interface (swallowing it)

Similarly, encapsulation hides internal state and exposes only what's needed.

🧪 Code Example

Without Encapsulation ❌

cpp
class BankAccount {
public:
    string ownerName;
    double balance;    // Anyone can directly modify this!
};

int main() {
    BankAccount acc;
    acc.balance = -1000;  // 💥 Invalid state! No validation.
}

With Encapsulation ✅

cpp
class BankAccount {
private:
    string ownerName;
    double balance;

public:
    BankAccount(string name, double initialBalance)
        : ownerName(name), balance(initialBalance) {}

    // Getter — controlled read access
    double getBalance() const { return balance; }

    // Setter — controlled write access with validation
    bool deposit(double amount) {
        if (amount <= 0) return false;  // Validation!
        balance += amount;
        return true;
    }

    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance) return false;  // Validation!
        balance -= amount;
        return true;
    }
};

int main() {
    BankAccount acc("Alice", 1000);
    acc.deposit(500);         // ✅ balance = 1500
    acc.withdraw(200);        // ✅ balance = 1300
    // acc.balance = -1000;   // ❌ Compilation error! Private.
}

🔑 Encapsulation vs Data Hiding

AspectEncapsulationData Hiding
WhatBundling data + methods togetherRestricting access to internal data
HowUsing classesUsing access modifiers (private)
RelationshipData hiding is a subset of encapsulationPart of encapsulation

[!tip] Key Insight Encapsulation is not just about making fields private. It's about designing a controlled interface for how data is accessed and modified.

💡 Benefits

BenefitExplanation
Data ProtectionPrevents invalid states (e.g., negative balance)
FlexibilityInternal implementation can change without affecting external code
MaintainabilityChanges are localized to the class
TestabilityControlled interface = easier to write tests
Reduced CouplingExternal code depends on interface, not implementation

✅ Quick Revision

QuestionAnswer
What is encapsulation?Bundling data + methods and controlling access
How is it achieved?Using private fields + public getters/setters
Why not just make everything public?No validation, anyone can set invalid state
Is it just about private?No — it's about designing a controlled interface

[!quote] Key Takeaway Encapsulation = data + behavior in one unit + controlled access. It protects your object's state and gives you the power to change how things work without breaking who uses them.

📖 Interfaces

An interface defines a contract — a set of methods that any implementing class must provide. It specifies what to do, not how to do it.

Why Interfaces?

Code Example

java
// Java — Interfaces
interface Sortable {
    void sort();
}

interface Searchable {
    Object search(String query);
}

// A class can implement MULTIPLE interfaces
class ProductCatalog implements Sortable, Searchable {
    private List<Product> products;

    @Override
    public void sort() {
        Collections.sort(products, Comparator.comparing(Product::getName));
    }

    @Override
    public Object search(String query) {
        return products.stream()
            .filter(p -> p.getName().contains(query))
            .findFirst()
            .orElse(null);
    }
}
cpp
// C++ — Interfaces via pure virtual classes
class Sortable {
public:
    virtual void sort() = 0;
    virtual ~Sortable() {}
};

class Searchable {
public:
    virtual void* search(const string& query) = 0;
    virtual ~Searchable() {}
};

// Multiple "interface" inheritance
class ProductCatalog : public Sortable, public Searchable {
public:
    void sort() override { /* implementation */ }
    void* search(const string& query) override { /* implementation */ }
};

[!tip] C++ Note C++ doesn't have a dedicated interface keyword. Interfaces are achieved using abstract classes with only pure virtual functions.

📖 Enums

An enum (enumeration) is a special type that defines a fixed set of named constants. In LLD, enums are used everywhere for type-safety.

Why Enums?

Without enums:

cpp
// BAD — Using strings 😬
string vehicleType = "CAR";  // Typo "car" or "Car" could cause bugs!

With enums:

cpp
// GOOD — Using enum ✅
enum class VehicleType { CAR, MOTORCYCLE, TRUCK, BUS };
VehicleType type = VehicleType::CAR;  // Type-safe, no typos possible

Java Enum with Methods

java
public enum OrderStatus {
    PENDING("Order is being processed"),
    CONFIRMED("Order is confirmed"),
    SHIPPED("Order has been shipped"),
    DELIVERED("Order delivered successfully"),
    CANCELLED("Order was cancelled");

    private final String description;

    OrderStatus(String description) {
        this.description = description;
    }

    public String getDescription() {
        return description;
    }
}

// Usage
OrderStatus status = OrderStatus.SHIPPED;
System.out.println(status.getDescription());
// Output: "Order has been shipped"

⚖️ Interfaces vs Abstract Classes (Revisited)

FeatureInterfaceAbstract Class
MethodsAll abstract (Java 7-)Can mix abstract + concrete
FieldsOnly constantsCan have instance fields
Constructors❌ No✅ Yes
Multiple inheritance✅ A class can implement many❌ Only one parent class
Use whenDefining a capabilitySharing code across a hierarchy

✅ Quick Revision

ConceptDescription
InterfaceContract defining what methods a class must implement
EnumFixed set of named constants for type-safety
Why interfaces?Loose coupling, multiple inheritance, testability
Why enums?No typos, IDE support, type-safe constants

[!quote] Key Takeaway Interfaces define contracts for what objects can do. Enums define fixed sets of values for what things can be. Together, they make your LLD designs type-safe, flexible, and clean.

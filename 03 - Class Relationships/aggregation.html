📖 What is Aggregation?

Aggregation is a special form of association that represents a HAS-A relationship where the child can exist independently of the parent.

[!example] Real-World Analogy 🏫 A Department has Professors. If the department is dissolved, the professors still exist — they can join another department.

[!tip] UML Notation Aggregation uses an empty diamond (◇) on the parent side.

🧪 Code Example

cpp
class Professor {
    string name;
public:
    Professor(string n) : name(n) {}
    string getName() { return name; }
};

class Department {
    string name;
    vector<Professor*> professors;  // Aggregation — doesn't own professors
public:
    Department(string n) : name(n) {}
    void addProfessor(Professor* p) { professors.push_back(p); }

    ~Department() {
        // Does NOT delete professors — they exist independently
        professors.clear();
    }
};

int main() {
    Professor p1("Dr. Smith"), p2("Dr. Jones");

    {
        Department dept("Computer Science");
        dept.addProfessor(&p1);
        dept.addProfessor(&p2);
    }  // Department destroyed, but professors still exist!

    cout << p1.getName() << " is still alive!" << endl;  // ✅
}

🔑 Key Properties

PropertyAggregation
RelationshipHAS-A (weak ownership)
Child can exist without parent?✅ Yes

[!quote] Key Takeaway Aggregation = "has a, but doesn't own." The child can outlive the parent.

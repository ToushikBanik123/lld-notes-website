📌 Prototype Pattern

🎯 What is the Prototype Pattern?

The Prototype Pattern is used to create duplicate objects by cloning an existing instance (a prototype) rather than constructing a new one from scratch.

[!example] Real-World Analogy 🖨️ Think of a Photocopy Machine. If you need to prepare 10 offer letters, you don't type out the exact same 5-page letter 10 times. You type it once (the Prototype), photocopy it 9 times, and just change the name at the top of each copy.

⚠️ The Problem

Imagine an Email Notification System where initializing an email is very expensive (loading templates from disk, parsing tokens, fetching fonts).

cpp
// ❌ BAD PRACTICE — Rebuilding from scratch
int main() {
    // Slow! Loads templates, parses tokens from scratch
    WelcomeEmail email1;
    email1.send("user1@example.com");

    // Slow! Does all the heavy lifting again
    WelcomeEmail email2;
    email2.setContent("Hi! Welcome to Premium");
    email2.send("user2@example.com");
}

🛠️ The Solution: Clone Mechanism

Instead of using new every time, we implement a clone() method. In C++, this usually involves leveraging the Copy Constructor.

1. Prototype Interface

cpp
class EmailTemplate {
public:
    virtual ~EmailTemplate() = default;
    
    // The core of the pattern: return a copy of yourself
    virtual unique_ptr<EmailTemplate> clone() const = 0;
    
    virtual void setContent(const string& content) = 0;
    virtual void send(const string& to) const = 0;
};

2. Concrete Prototype

cpp
class WelcomeEmail : public EmailTemplate {
private:
    string content;
    vector<string> expensiveTemplateTokens;

public:
    WelcomeEmail() {
        // Expensive initialization...
        expensiveTemplateTokens = {"{name}", "{link}"}; 
        content = "Welcome!";
    }

    // Use default copy constructor for Deep Copying (vectors copy by value in C++)
    WelcomeEmail(const WelcomeEmail& other) = default;

    unique_ptr<EmailTemplate> clone() const override {
        // Create a new instance using the copy constructor
        return make_unique<WelcomeEmail>(*this);
    }

    void setContent(const string& c) override { content = c; }
    void send(const string& to) const override { 
        cout << "Sending to " << to << ": " << content << "\n"; 
    }
};

3. Registry & Client

We often use a Registry to store the base prototypes.

cpp
class EmailRegistry {
    unordered_map<string, unique_ptr<EmailTemplate>> templates;
public:
    void registerTemplate(const string& key, unique_ptr<EmailTemplate> proto) {
        templates[key] = std::move(proto);
    }

    unique_ptr<EmailTemplate> getTemplate(const string& key) {
        return templates[key]->clone(); // Hand out a clone!
    }
};

int main() {
    EmailRegistry registry;
    registry.registerTemplate("welcome", make_unique<WelcomeEmail>()); // Heavy work done ONCE

    // Fast object creation via cloning!
    auto email1 = registry.getTemplate("welcome");
    email1->setContent("Hi Alice!");
    
    auto email2 = registry.getTemplate("welcome");
    email2->setContent("Hi Bob!");
}

🌊 Deep Copy vs Shallow Copy

The trickiest part of the Prototype pattern (especially in C++) is managing memory pointers.

  • Shallow Copy: Copies the memory address. If the clone modifies the data, the original object is modified too! (Bad for Prototypes).
  • Deep Copy: Allocates new memory and copies the actual values. The clone is 100% independent.

[!tip] C++ Tip Standard containers like std::vector or std::string do deep copies automatically in copy constructors. If you have raw pointers (int* data), you MUST write a custom copy constructor to allocate new int and copy the value.

✅ Pros and Cons

ProsCons
Performance: Skips costly initialization logicComplexity: Implementing deep copies for objects with circular references is very difficult
Runtime Flexibility: Clone objects without coupling to concrete classes

[!quote] Key Takeaway Use the Prototype pattern when creating an object from scratch is more expensive or complex than simply copying an existing instance and modifying it.

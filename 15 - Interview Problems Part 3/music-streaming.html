📌 Designing a Music Streaming Platform

🎯 Step 1: Clarify Requirements

Functional Requirements

  1. Media: Play Songs, Albums, Playlists.
  2. Controls: Play, Pause, Skip, Shuffle, Repeat.
  3. Delivery: Byte-range streaming over HTTP (chunked).
  4. Offline: Premium users can download songs (device limits apply).
  5. History: Record listening history to generate recommendations.

Non-Functional Requirements

  1. Caching: Hot songs should be cached in LRU memory to prevent hitting the storage repository repeatedly for file chunks.

🧱 Step 2: Identify Core Entities

  1. Song, Album, Playlist: Media metadata.
  2. PlaybackSession: Links a User, a Device, the current Queue, Shuffle/Repeat states, and current byte position.
  3. CacheService: LRU cache storing byte chunks (vector<uint8_t>) mapped by songId_start_end.

⚙️ Step 3: Architecture & Streaming Simulation

Real streaming uses HTTP 206 Partial Content. In LLD, we simulate this using a StreamingService that receives a byte range, checks the CacheService, and returns a vector<uint8_t>.

💻 Step 4: Core Implementation (C++)

cpp
#include <iostream>
#include <string>
#include <vector>
#include <unordered_map>
#include <list>
#include <memory>

using namespace std;

// 1. Media Entities
struct Song {
    string id;
    long fileSize;
};

// 2. LRU Chunk Cache
class CacheService {
    int maxSize;
    list<string> lruKeys;
    unordered_map<string, pair<vector<uint8_t>, list<string>::iterator>> cache;

public:
    CacheService(int size) : maxSize(size) {}

    bool getChunk(const string& key, vector<uint8_t>& outChunk) {
        if (cache.find(key) != cache.end()) {
            lruKeys.erase(cache[key].second);
            lruKeys.push_front(key);
            cache[key].second = lruKeys.begin();
            outChunk = cache[key].first;
            return true;
        }
        return false;
    }

    void putChunk(const string& key, const vector<uint8_t>& chunk) {
        if (cache.size() >= maxSize) {
            string lru = lruKeys.back();
            lruKeys.pop_back();
            cache.erase(lru);
            cout << "[Cache] Evicted: " << lru << endl;
        }
        lruKeys.push_front(key);
        cache[key] = {chunk, lruKeys.begin()};
        cout << "[Cache] Stored: " << key << endl;
    }
};

// 3. Streaming Service
class StreamingService {
    CacheService cache;
public:
    StreamingService() : cache(3) {} // Max 3 chunks for demo

    vector<uint8_t> streamChunk(Song& song, long start, long end) {
        string key = song.id + "_" + to_string(start) + "_" + to_string(end);
        vector<uint8_t> data;

        if (cache.getChunk(key, data)) {
            cout << "Served from cache: " << key << endl;
            return data;
        }

        // Simulate fetching from Disk/S3
        cout << "Fetching from Storage... " << key << endl;
        data = vector<uint8_t>(end - start, 0xFF); // Mock data
        
        cache.putChunk(key, data);
        return data;
    }
};

int main() {
    Song s1 = {"S1", 1024};
    StreamingService streamer;

    streamer.streamChunk(s1, 0, 100);
    streamer.streamChunk(s1, 100, 200);
    streamer.streamChunk(s1, 0, 100); // Hits Cache
    streamer.streamChunk(s1, 200, 300);
    streamer.streamChunk(s1, 300, 400); // Evicts S1_100_200

    return 0;
}

🚨 Edge Cases Handled

  • Cache Eviction: An LRU (Least Recently Used) cache prevents memory exhaustion from high-traffic streaming.
  • Concurrent Playlist Modification: When adding/removing songs to a playlist, an application-level mutex per playlist ensures that vector bounds don't crash the server.
